傳統 ETL 遇到傳產工廠的合併儲存格、民國年、千分位逗號時會直接中斷拋錯。A03 Headless ETL 透過 5-Stage 解耦管線，實現 100% 容錯與唯一 Hash 主鍵冪等寫入：

Pipeline 階段 傳產現場痛點 Headless ETL 核心演算法 (0-Token Hard Compute) 輸出成果與防呆機制
Stage 1: Header Detector 多行標題、上層說明文字、合併儲存格跨列 掃描前 8 列，定位非空率 ≥ 60% 之最後列作為表頭；openpyxl 進行 forward_fill 向下/向右自動展開 自動展平為單一正規列，消除 NaN 欄名
Stage 2: Schema Inferencer 每月份欄位格式微調、數字 ID 遭誤判截斷 抽樣前 100 列，嚴格遵循推斷優先序：DATE > INTEGER > REAL > TEXT；欄名含「編號/ID」強制鎖定 TEXT_ID 動態生成 SQLite DDL，避免字串與數字混雜報錯
Stage 3: Dirty String Parser 民國年 (112/10/25)、斜線日期、千分位金額 ($1,234,567) Taiwan-first Date Parser (ROC 年份自動 +1911 轉 ISO YYYY-MM-DD)；Regex 清除 ,，$$＄% 並轉 REAL 轉換失敗自動 fallback 保留原始 TEXT，記入錯誤記錄
Stage 4: Upsert Writer 每日重跑資料重複、無明確 Primary Key 計算整列拼接之 SHA256(row_values)[:16] 作為代理唯一主鍵 (Surrogate PK)，執行 INSERT OR REPLACE 保證冪等性 (Idempotent)，並啟用 WAL 模式加速
Stage 5: Error Report 管線拋出 Exception 導致排程崩潰中斷 管線不崩潰，異常欄位獨立輸出 error_report_YYYYMMDD_HHMMSS.csv 記錄欄名、原始值與錯誤類別 維運人員一鍵查閱修復，生產環境 0 宕機

# headless_etl.py: Taiwan-First Date Parser & Surrogate PK
ROC_YEAR_OFFSET = 1911
DATE_PATTERNS = [
    (r'(\d{3})年(\d{1,2})月(\d{1,2})日', 'roc_full'),
    (r'(\d{3})/(\d{1,2})/(\d{1,2})', 'roc_slash'),
    (r'(\d{4})-(\d{2})-(\d{2})', 'iso'),
]

def parse_date(val):
    val = str(val).strip()
    for pattern, mode in DATE_PATTERNS:
        m = re.fullmatch(pattern, val)
        if m and mode in ('roc_full', 'roc_slash'):
            y = int(m.group(1)) + ROC_YEAR_OFFSET
            return f"{y:04d}-{int(m.group(2)):02d}-{int(m.group(3)):02d}"
    return None

def clean_amount(val):
    cleaned = re.sub(r'[,，\$＄\s%元NT]', '', str(val)).strip()
    return float(cleaned) if cleaned else 0.0
